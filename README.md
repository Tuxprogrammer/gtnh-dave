# gtnh-dave

Dave is an AI agent that lives in the chat of a GT New Horizons server. Players ask him questions in game ("dave, what's the EU/t of the EBF steel recipe?") and he answers in chat. To do that he reads the pack's source code, looks up recipes exported from the pack itself, and runs small Groovy scripts against the live server.

He was built for a small private GTNH 2.9.0 server with trusted players. This repo is the reusable part: the mod, the agent and the tools that build his pack knowledge. It has no server setup, deploy files or pack data; you bring your own server and build the data from your own pack.

Dave runs on the **Claude Code CLI** with a Claude subscription, not with API tokens.

## How it works

```
┌───────────────────────┐  FML packets  ┌──────────────────────────────┐  WebSocket (token)  ┌──────────────────────┐
│ Player client         │ ◀───────────▶ │ GTNH 2.9.0 server            │ ◀─────────────────▶ │ Dave daemon          │
│  └─ DaveBridge (opt.) │  ask/context  │  └─ DaveBridge (server side) │  chat / say / eval  │ (MCP server + bridge)│
│      • context capture│  messages     │      • chat hooks + relay    │                     └──────────┬───────────┘
│      • client eval    │  client eval  │      • main-thread queue     │                                │ stream-json
│        (opt-in)       │               │      • Groovy eval           │                     ┌──────────▼───────────┐
└───────────────────────┘               └──────────────────────────────┘                     │ claude -p (long-lived)│
  vanilla-chat players work too                                                              │ reads gtnh-src/, wiki │
                                                                                             └──────────────────────┘
```

1. **DaveBridge** is one Forge mod jar with a server side and a client side.
   - **Server side (required).** It forwards chat that starts with a trigger (`dave`, `@dave`, `!dave`; `Dave how…` and `Dave, …` both count) over a WebSocket that requires a token. Replies are queued and shown as `<Dave>` on the server thread. It is the **only** link to Claude, and it relays traffic for clients.
   - **Client side (optional).** Players without it still use Dave through plain chat. With it, questions carry context (what the player is looking at or holding, which GUI is open), Dave's replies render with clickable NEI/quest/waypoint links, and Dave can show a ghost demonstration in the player's world. Dave can also run code on that player's client, but only if the player opts in with `clientEvalAllowed`, which is off by default.
2. **The Dave daemon** (`dave/daemon/`) holds the socket. The `bridge` MCP server (`dave/bridge/`) exposes the game to Claude through it as MCP tools: `say`, `eval`, `describe`, `lesson`, the saved-query library, event hooks (`hook_add`: Dave is told when something happens in the game) and `undo` for confirmed world changes (see `dave/TOOLS.md`).
3. **Claude** runs as one long-lived `claude -p --input-format stream-json --output-format stream-json` process. To answer a question about any mod, it greps the decompiled pack in `gtnh-src/`, looks up the recipe database and the search index, then writes a Groovy script and runs it in the live server. No mod needs a hand-written connector.

## Layout

| Path | What |
|---|---|
| `DaveBridge/` | The Forge mod, built from [Tuxprogrammer/ExampleMod1.7.10](https://github.com/Tuxprogrammer/ExampleMod1.7.10). The wire format is in `DaveBridge/PROTOCOL.md` |
| `dave/` | The daemon, the MCP servers (`bridge`, `dave-memory`), the launch config (`dave/launch/`), Dave's prompt (`dave/soul/`), saved queries and `config.toml` |
| `tools/` | Pack knowledge: `decomp/` (builds `gtnh-src/`), `recipe-export/` and `recipes/` (recipe database and LP planner), `gtnh-search/` (semantic search over quests, wiki, GuideNH), `living-wiki/`, `planner/` (the GTNH planner site's agent API), `packstate.py` and `refresh-pack-data.sh` |
| `data/` | Generated and local: the search corpus and embeddings, `recipes.sqlite`, pack stamps, and Dave's memories (they hold player data). Git-ignored apart from `data/memory/README.md` |
| `gtnh-src/` | Generated by `tools/decomp/`: the pack's mod source (real upstream checkouts plus decompiles remapped to MCP names) with its indexes. Git-ignored |
| `.work/` | Downloaded pack archives and scratch files. Git-ignored |

## Getting started

You need a GTNH 2.9.0 server you control (Java 17+ via lwjgl3ify), Python 3.11+, and Claude Code logged in with a subscription.

1. **Build and install DaveBridge.** `cd DaveBridge && ./gradlew build`, then put the jar on the server (and, optionally, on players' clients). In the server's `config/davebridge.cfg`, set `authToken` (the same value goes in Dave's `DAVE_BRIDGE_TOKEN`), and `bindAddress`/`port` (default 25580) if the daemon runs elsewhere; `/dave status` and `/dave reload` help. Never publish the WebSocket port: keep the daemon on the same host or private network.
2. **Build Dave's pack knowledge from your pack.** Extract the GTNH server pack to `.work/gtnh-<version>/pack/` (or set `GTNH_PACK_DIR`), then run `tools/refresh-pack-data.sh`. It builds `gtnh-src/`, exports the recipe database with a headless throwaway server, extracts the search corpus and embeds it, rebuilding only what is stale. Embeddings use OpenRouter (`OPENROUTER_API_KEY` in a git-ignored `.env`); that is the only API key involved. Each tool's README or header has the details.
3. **Configure and start Dave.** Settings are in `dave/config.toml`, each overridable by an environment variable. Put `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`) and `DAVE_BRIDGE_TOKEN` in `dave/.env` (git-ignored). Check the setup with `python3 -I dave/launch/dave_cmd.py --print` and `--probe`, then run `python3 -I dave/daemon/main.py`.

Extra mods on top of GTNH can be layered in as packwiz packs (`TUXMINE_DIR`, see `tools/packstate.py`); their jars are added to `gtnh-src/`, the recipe export and the search corpus like the base pack.

## Project root

By default everything Dave builds lives inside this checkout. To keep your data, deploy files and site config in a separate (private) repo, add this repo to it as a submodule and put a file named `dave-agent.root` in that project's root, next to the submodule. The tools and `dave/config.py` then use that directory as the root for `data/`, `gtnh-src/`, `.work/` and the extra packs. `DAVE_AGENT_ROOT` (tools) and `DAVE_ROOT` (Dave's config) still override it.

Some code comments cite design notes under `docs/plans/`; those are kept in the author's private project.

## Running Dave on a subscription

- Log in with `claude login`. On a headless box, use `claude setup-token` and set `CLAUDE_CODE_OAUTH_TOKEN`.
- `ANTHROPIC_API_KEY` must **not** be set in the daemon's environment. If it is, the CLI bills the API instead of the subscription.
- Don't pass `--bare`. It only accepts API-key auth.
- Dave's usage counts against the same 5-hour and weekly limits as your own Claude use. The daemon rate-limits players with per-player cooldowns and queue caps.

## Trust model

Dave was built for a private server whose whitelist holds only trusted players. He can run arbitrary code inside the server JVM **on purpose**. The safeguards are there to prevent accidents, not attacks:

- Payloads run on the main thread under a per-tick time budget, with interrupt checks compiled into their loops and calls.
- Exceptions are caught and sent back to Dave, so they never reach the server.
- Result sizes are capped.
- A blocklist catches obvious footguns such as `System.exit` and server shutdown.
- Scripts that change the world need the player to confirm them in chat.
- Dave runs code on a player's own client only if that player turns on `clientEvalAllowed` in their client config. It is off by default, because that code runs on their machine, not the server.

**Don't run Dave on a server with untrusted players.** That would need a different design.
